# 小红书黑马爆文榜核心流程

> 本文件为 Agent 执行本技能的完整流程说明。SKILL.md 只保留用户面向内容，Agent 执行时必须遵循本文件中的所有规则。

## 使用边界

- 每次调用数据服务都可能消耗积分；只执行用户明确要求的分类与统计窗口，不主动批量查询多个分类。
- 查询无结果时如实说明并给出可调整方向（如更换分类 / 更近的窗口），不自动改查其他分类或其他内容。
- 主查询流程最多 2 次数据请求（首次查询 + 空数据或超窗时的自动回退）。
- HTML 文件包生成时从本地缓存读取，不重复请求数据服务（0 次请求）。
- 订阅推送由平台侧定时任务触发（每日 19:30），不在查询流程内重复订阅。

## 意图识别与参数准备

1. 识别用户想查询的**分类**（可不指定，默认「综合全部」）与**统计窗口开始日期**（可不指定）。
2. 将自然语言分类词映射到 25 个标准分类之一（匹配规则见下）；将自然语言日期词转换为具体日期。
3. 调用主脚本获取数据。

## 主查询流程

脚本：`scripts/fetch_darkhorse_articles.py`

默认调用：

```bash
python scripts/fetch_darkhorse_articles.py --keyword "居家装修"
```

常用参数：

```bash
python scripts/fetch_darkhorse_articles.py --category "潮流鞋包"
python scripts/fetch_darkhorse_articles.py --keyword "穿搭"
python scripts/fetch_darkhorse_articles.py --rank_date "2026-09-08" --keyword "居家装修"
python scripts/fetch_darkhorse_articles.py --rank_date "2026-09-08" --show_all
```

参数规则：

| 参数 | 说明 |
|---|---|
| `--category` | 直接指定标准分类名，默认「综合全部」 |
| `--keyword` | 用户输入的关键词，用于自动匹配分类（优先于 `--category`） |
| `--rank_date` | 统计窗口开始日期，支持传具体日期或「昨天」「三天前」「一周前」等模糊日期词 |
| `--top_n` | 返回前 N 条，默认 50 |
| `--show_all` | 输出 Top21-50（用于「查看更多」） |
| `--no_fallback` | 禁用自动回退；指定日期报错或无数据时直接返回原因，不自动改查默认窗口 |

### 分类匹配规则

匹配优先级：① 精确匹配标准分类名 → ② 关键词命中分类关键词表（双向包含） → ③ 未命中则回退「综合全部」。匹配结果不在 25 个标准分类内时同样回退「综合全部」。

25 个标准分类：综合全部、出行代步、医疗保健、休闲爱好、综合杂项、婚庆婚礼、居家装修、影视娱乐、星座情感、拍摄记录、学习教育、旅行度假、亲子育儿、日常生活、科学探索、数码科技、时尚穿搭、化妆美容、个人护理、美味佳肴、职业发展、宠物天地、新闻资讯、体育锻炼、潮流鞋包。

### 日期处理规则

- 数据每天 **17:30** 开始更新昨日数据；17:30 前查询昨日窗口会返回成功但 0 条数据。
- 用户未指定日期时：≥17:30 默认查**昨天**，<17:30 默认查**前天**。
- 回退窗口固定为**7 天前**当日（实测稳定可用）。
- `rankDate` 为统计窗口的**开始日期**，接口文档标注最长回溯 30 天，实测按单日出榜（返回笔记发布日期集中在 rankDate 当天或前一天）。
- 指定日期返回「日期格式错误」等日期类报错或空数据时，脚本**自动回退**用默认窗口重查一次；`--no_fallback` 可关闭该回退。
- 支持模糊日期词：今天/今日、昨天/昨日、前天/前日、大前天、一周前、半个月前、一个月前。

### 鉴权与来源标识

- 鉴权请求头：`REDFOX_API_KEY: <REDFOX_API_KEY>`。
- API Key 三级回退读取：① 当前环境变量 `REDFOX_API_KEY` → ② shell 配置文件（macOS/Linux：`.zshrc`、`.bashrc`、`.bash_profile`、`.profile`；Windows：PowerShell profile、`~/.bashrc`、`~/.bash_profile`）→ ③ 未找到则打印获取与配置指引。
- 来源标识：请求体携带 `source` 字段，值为「小红书黑马爆文榜-GitHub」。
- API Key 获取：访问 [红狐 hub](https://redfox.hk/settings/api-keys?source=github) 注册账号并获取（格式 `ak_xxxxxxxx`）。

### 输出结构（严格按顺序）

脚本一次输出四部分，Agent 必须**原样完整输出**（脚本内已带格式保护声明）：

1. **黑马爆文榜表格**：序号、笔记信息（标题链接 + 作者主页链接 + 粉丝数）、互动总数、点赞数、评论数、收藏数、分享数、发布时间。首次输出 Top1-20；总数超过 20 条时附「可以输入"查看更多"展示剩余榜单」提示。
2. **爆款规律分析**：基于全部获取数据（50 条）生成——① 标题特征表（标题类型 / 特征 / 占比 / 标题模版 / 描述 / 参考笔记）；② 内容主题表（内容分类 / 特征 / 占比 / 实际效果 / 参考笔记）；③ 可参考亮点列表。参考笔记均带可跳转链接。
3. **分类查询提示**：列明 25 个可选分类，引导用户按分类继续查询。
4. **功能选择入口**：① 订阅（回复「订阅」或「1」）；② 导出 HTML 文件包（回复「2」）。

自动回退日期时，在输出最前面注明「指定日期超出窗口/暂无数据，已自动回退查询统计窗口开始日期 XXXX-XX-XX」。

字段口径：`photoId`/`userId` 拼接笔记与作者主页链接；`interactiveCount` 为空或 ≤0 时按 点赞+收藏+评论+分享 求和兜底；`2w+`、`4w+` 等格式按 1w=10000 换算后排序展示；按互动总量降序取 Top50。

### 缓存产物

主脚本在生成 md 报告的同时输出 `*_cache.json` 缓存文件（含完整 articles 列表），供 HTML 生成复用。

## HTML 文件包生成（节能 + 自动展示）

用户回复「2」时，按以下两步执行，**缺一不可**：

**第一步：生成 HTML（不请求数据服务）**

- 优先从缓存文件渲染：`generate_html_on_demand.py --from-cache ./小红书XX黑马爆文榜_xxx_cache.json --output ./output.html`（0 次请求）。
- 缓存不可用时回退重新取数：`generate_html_on_demand.py --rank_date 2026-09-08 --keyword 居家装修 --output ./output.html`。
- 页面模板读取自 `assets/preview-template.html`。

```bash
# 节能模式：从缓存生成 HTML（0 次请求）
python generate_html_on_demand.py --from-cache ./小红书居家装修黑马爆文榜_xxx_cache.json --output ./output.html

# 回退模式：重新请求数据后渲染（仅缓存缺失时使用）
python generate_html_on_demand.py --rank_date 2026-09-08 --keyword 居家装修 --output ./output.html
```

**第二步：自动展示 + 发送文件（必须按顺序执行）**

1. 优先使用 `preview_url` 打开该文件，让用户直接看到可视化页面。
2. 若 `preview_url` 未正常展示（含中文路径等兼容问题），立即改用 `open_result_view` 兜底展示。
3. 使用 `deliver_attachments` 将 HTML 文件作为附件发送给用户。
4. 完成后告知用户文件保存路径。

## 订阅推送

- 用户回复「订阅」或「1」后，平台侧定时任务每日 **19:30** 推送最新黑马爆文榜 TOP50。
- 数据 17:30 开始更新，故推送时当日最新数据已就绪。
- 每次订阅一个分类，更换分类需重新订阅。

## 错误处理

- **业务错误（含日期类报错）**：优先展示接口返回的 `msg`；日期类报错或无数据时按「日期处理规则」自动回退一次。
- **空数据**：输出「当前查询窗口暂无黑马爆文数据，可尝试更换分类或稍后再查」。
- **缺少 API Key**：打印获取与配置指引，提示用户配置 `REDFOX_API_KEY`，禁止硬编码密钥。
- **网络/HTTP 异常**：仅连接层异常最多重试 3 次（超时 45 秒）；业务响应一旦到达即不再重试，避免重复扣积分。

## 积分与性能

- 每次调用扣积分（含返回空数据的请求）。
- 主查询流程最多 2 次请求（首次 + 空数据/超窗回退）；业务报错不反复重试；HTML 生成走缓存不再请求。

## 数据流转

- **主查询流程**：用户输入分类关键词 → 匹配标准分类 → 请求数据服务（最多 2 次） → 清洗数据（链接拼接、互动总数兜底） → 按互动量降序取 TOP50 → 生成榜单表格 + 缓存 JSON → 分析标题特征与内容主题 → 输出完整报告。
- **HTML 生成流程**：用户选择导出 → 读取缓存 JSON（0 次请求） → 渲染 HTML 页面 → 自动展示 → 告知保存路径。
